## レビューの観点

仕様

- Issue・仕様の各 AC が満たされているか。受け入れテストが通るだけでなく、AC の意図どおりに動くか。
- AC ごとに受け入れテスト（`e2e/`）があり、AC の番号と対応しているか。テストが AC を緩めていないか。
- 画面の URL と文言が仕様と一致しているか。「対象外」のことや、頼まれていない機能を足していないか。

コード

- Next.js 16 の書き方に沿っているか（Server Component と Client Component の使い分け）。
- Supabase へは `src/lib/supabase/` を通して接続しているか。
- 変えた部分に単体テストがあり、意味のあることを確かめているか。
- 使っていないコード・デバッグ用の出力が残っていないか。依存パッケージを増やしていれば、その必要があるか。

安全性とデータ

- 新しいテーブルで RLS が有効で、ポリシーが広すぎないか。migration は新しいファイルとして足されているか。
- 秘密の値をコードに書いたり、ブラウザに渡したりしていないか。
- 入力の長さ・形式をサーバー側でも確かめているか。エラーのときに内部の情報を画面に出していないか。

仕様の PR のときは、要件を満たしているか、AC と文言が具体的か、既存の画面と矛盾しないかを見る。

細かい好みの違いは指摘しない。動作・保守に影響するものだけを指摘する。

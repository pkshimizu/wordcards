- 受け入れテストは `e2e/` に Playwright で書く。ファイル名は `e2e/<機能>.spec.ts`（例：`e2e/cards.spec.ts`）。
- 1つの AC につき 1つの `test` にする。テスト名は `AC1: ...` のように AC の番号から始める。
- 要素は Issue の「画面の URL・文言」に書かれた文言で探す。`getByRole`（ボタン・見出し・リンク）と `getByLabel`（入力欄）を優先し、CSS セレクタや `data-testid` は使わない。
- 画面の文言は Issue に書かれたとおりに一字一句合わせる。Issue に無い文言を前提にしない。
- 待ち合わせは `expect(...).toBeVisible()` などの自動待ちを使う。`waitForTimeout` は使わない。
- テストを流す前に `npm run db:reset` で DB を空にして seed を入れ直す。テストは1つずつ順に流れる（workers: 1）。
  - 前提（Given）に必要なデータは `supabase/seed.sql` に足す。既存の seed は消さない。
  - あるテストが作ったデータで、別のテストが壊れないようにする（件数ではなく、そのテストで入れた文言で確かめる）。
- 「カードが1枚もない」のように空の状態が前提の AC は、seed に入れたデータの影響を受けない書き方にするか、Issue に合わせて seed を分けずに済む形を選ぶ。どうしても両立しないときは、そのことを結果に書く。
- アプリのコード（`src/` や `supabase/migrations/`）は書かない。まだ無い画面のテストが失敗するのは正しい状態。
- 既存のテスト（`e2e/home.spec.ts` など）は消さない・変えない。

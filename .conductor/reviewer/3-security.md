安全性とデータを確かめる。

- 新しいテーブルで RLS（行ごとのアクセス制限）が有効になっていて、ポリシーが広すぎないか。
- migration は新しいファイルとして足されているか。既存の migration を書き換えていないか。
- 秘密の値（service role キーなど）をコードに書いたり、ブラウザに渡したりしていないか。`NEXT_PUBLIC_` を付けてよいのは公開してよい値だけ。
- ユーザーの入力をそのまま SQL や HTML に入れていないか。入力の長さ・形式をサーバー側でも確かめているか。
- エラーのときに内部の情報（SQL・スタックトレース）を画面に出していないか。

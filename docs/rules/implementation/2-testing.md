# テスト

## 単体テスト

- 変えた部分には vitest の単体テストを足す。テストは対象のファイルの隣に `*.test.ts(x)` で置く。
- 乱数や時刻を使う処理は、差し替えられるように引数で受け取る関数に切り出して確かめる。

## 受け入れテスト

- 受け入れ条件（AC）ごとに、受け入れテストを `e2e/<機能>.spec.ts` に Playwright で書く。1 つの AC につき 1 つの `test` にし、テスト名は `AC1: ...` のように AC の番号から始める。
- 要素は仕様の文言で探す。`getByRole` と `getByLabel` を優先し、CSS セレクタや `data-testid` は使わない。`waitForTimeout` は使わない。
- 前提（Given）に必要なデータは `supabase/seed.sql` に足すか、テストの中で画面から作る。既存の seed と既存のテストは、仕様が変わったとき以外は消さない・変えない。
- あるテストが作ったデータで別のテストが壊れないようにする（件数ではなく、そのテストで入れた文言で確かめる）。
- 流し方: `npm run db:reset` のあと `npm run test:e2e`。
- ポート 3100 で別の開発サーバーが動いていると、Playwright はそのサーバーを使ってしまう（新しい画面が無く 404 になる）。そのサーバーは止めず、一時的な設定で別のポートに `next start` を立てて流す。一時的な設定はコミットしない。

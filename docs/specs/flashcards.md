# カードモード

- 要件: 1574335613631467533（投稿者 kenji.shimizu）
- 要件の本文: 「カードを一枚ずつランダムに表示し、表をクリックしたら裏を表示し、裏を表示したら次のカードをランダムに表示するカードモードを追加する」

## 目的

答えを入力せずに、カードをめくるだけで単語と意味を次々に見返せるようにする。
紙の単語カードのように、表を見て意味を思い浮かべ、めくって裏を確かめ、次のカードへ進む。

## 既存の機能との関係

| 機能                     | URL           | 出し方                                 | 答えの入力 | 答えの結果の保存 |
| ------------------------ | ------------- | -------------------------------------- | ---------- | ---------------- |
| カードで出題する         | `/quiz`       | 新しく登録した順                       | あり       | する             |
| 間違えたカードを復習する | `/review`     | 新しく登録した順（不正解のカードだけ） | あり       | する             |
| カードモード（今回）     | `/flashcards` | ランダム                               | なし       | しない           |

- カードモードは `/quiz`・`/review` とは別の画面として追加する。`/quiz`・`/review`・`/cards` の振る舞いと文言は変えない。
- カードモードは正誤を判定しないので、答えの結果（`card_results`）を読まず、書き込まない。カードモードでカードを何回見ても、`/review` に出るカードは変わらない。
- データの持ち方（テーブル・列）は変えない。既存の `cards` の `front`（表）・`back`（裏）を読むだけ。

## 利用者から見た振る舞い

### 画面の流れ

1. 利用者が `/flashcards` を開く。
2. 登録されているカードのうち 1 枚がランダムに選ばれ、その**表**が表示される。
3. 利用者がカードを押すと、同じカードの**裏**が表示される（表は表示されなくなる）。
4. 利用者がもう一度カードを押すと、次のカードがランダムに選ばれ、その**表**が表示される。
5. 3〜4 を、利用者がやめるまで繰り返す。終わりの画面はない。
6. やめるときは、リンク「カード一覧へ」で `/cards` へ移動する（またはブラウザで別のページへ移動する）。

### 画面の URL・文言

`/flashcards`（カードモード）

| 要素                   | 文言・内容                                                                                                                   |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 見出し（h1）           | 「カードモード」                                                                                                             |
| カード                 | 1 個のボタン。中に「面のラベル」と「カードの文字」を表示する                                                                 |
| 面のラベル             | 表を表示しているとき「表」、裏を表示しているとき「裏」                                                                       |
| カードの文字           | 表を表示しているときはカードの表、裏を表示しているときはカードの裏                                                           |
| 操作の説明             | 表を表示しているとき「カードを押すと裏を表示します」、裏を表示しているとき「カードを押すと次のカードを表示します」           |
| リンク                 | 「カード一覧へ」（行き先 `/cards`）。カードが 0 枚のときも表示する                                                           |
| カードが 0 枚のとき    | 「カードがありません」（カードと操作の説明は表示しない）                                                                     |
| 読み込みに失敗したとき | `/quiz` と同じ。見出し「カードを読み込めませんでした」、「時間をおいてもう一度お試しください。」、ボタン「もう一度読み込む」 |

- 「面のラベル」「カードの文字」「操作の説明」は、それぞれ文言だけを持つ別々の要素にする（受け入れテストが `getByText(…, { exact: true })` で探せるようにする）。
- 画面の内容は `/quiz` と同じく `main` 要素の中に置く。カードが 1 枚以上あるとき、`main` の中のボタンはカードの 1 個だけにする（リンク「カード一覧へ」はボタンではなくリンクにする）。受け入れテストは、カードを `page.getByRole("main").getByRole("button")` で探す（`main` の外に開発サーバーが足すボタンなどを拾わないよう、範囲を `main` に限る）。
- カードが 0 枚のとき、`main` の中にボタンは 1 個もない。
- 読み込みに失敗したときの画面は別扱いで、上の「ボタンは 1 個だけ」の対象にしない。この画面のボタンは「もう一度読み込む」で、カードは表示しない。
- 表を表示している間は裏の文字を、裏を表示している間は表の文字を、画面に出さない（見えないだけでなく、要素としても置かない）。
- カードは `button` 要素にする。クリック・タップのほか、キーボード（フォーカスして Enter または Space）でも同じように操作できる。
- カードの文字は最大 200 文字（既存の上限）。長い文字は折り返して表示し、カードや画面の幅からはみ出さない。
- 何枚目か・全部で何枚かは表示しない。

### ランダムの決め方

- 対象は、`/flashcards` を開いた時点で登録されているすべてのカード。絞り込みはしない。
- カードは「一巡」を単位に出す。一巡の中では、すべてのカードを 1 回ずつ、ランダムな順で表示する。同じカードが一巡の中で 2 回出ることはない。
- 一巡が終わったら、もう一度ランダムな順を決め直して次の一巡を始める。これを利用者がやめるまで繰り返す。
- カードが 2 枚以上あるとき、同じカードを 2 回続けて表示しない（一巡の最後のカードと、次の一巡の最初のカードが同じにならないようにする）。
- カードが 1 枚だけのときは、そのカードを繰り返し表示する（表 → 裏 → 同じカードの表 → …）。
- 順番は、ページを開くたび（再読み込みを含む）に決め直す。前に開いたときの続きからにはしない。
- カードモードを開いている間に、別のタブなどでカードを追加・編集・削除しても、開いている画面には反映しない。開き直す（再読み込みする）と反映する。
- 表の文字が同じカードが複数あるときも、別々のカードとして 1 枚ずつ出す。「同じカード」かどうかは、文字ではなくカードの id で決める。
- 最初の一巡の順番は、サーバー側でページを開くたびに決めて画面へ渡す。ページを開いた直後から最初のカードの表が表示され、読み込み中の表示は挟まない。ブラウザ側の最初の描画では乱数を使わない（サーバーの描画とブラウザの描画が食い違わないようにする）。二巡目からの順番は、ブラウザ側で一巡が終わるたびに決める。

### 決めた理由（要件から読み取れなかった点）

| 点                       | 決めたこと                                                   | 理由                                                                                                                               |
| ------------------------ | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| 次のカードに進むきっかけ | 裏を表示しているカードをもう一度押す                         | 自動で進むと、裏を読む時間が人やカードによって足りない。表をめくる操作と同じ操作で進めるのが一番簡単                               |
| ランダムの決め方         | 一巡するまで同じカードを出さない。続けて同じカードを出さない | 覚えるための機能なので、すべてのカードを偏りなく見られるほうがよい。毎回完全にランダムだと、出ないカードや同じカードの連続が起きる |
| 対象のカード             | すべてのカード                                               | 要件に絞り込みの記述がない。`/quiz` もすべてのカードを対象にしている                                                               |
| 終わり方                 | 終わりはなく、やめるまで続く                                 | 要件が「裏を表示したら次のカードを表示する」とだけ書いており、終わりの記述がない。正誤を数えないので、見せる結果もない             |
| URL                      | `/flashcards`                                                | 既存の `/quiz`・`/review` と同じく、機能ごとに最上位の URL を 1 つ持たせる                                                         |
| 入り口                   | URL を直接開く                                               | 既存の `/quiz`・`/review` にも、ほかの画面からのリンクがない（画面どうしをつなぐメニューがまだない）                               |
| 戻り方                   | リンク「カード一覧へ」（`/cards`）                           | `/quiz` の結果の画面と同じ文言・行き先に合わせた                                                                                   |
| 答えの結果への影響       | なし                                                         | 正誤を判定しないので、保存する結果がない                                                                                           |

## 受け入れ条件（AC）

AC1〜AC10 は受け入れテスト（`e2e/flashcards.spec.ts`、Playwright）で確かめる。1 つの AC が 1 つの `test` に対応する。
受け入れテストの環境では作れない状態（カードが 0 枚・1 枚・ちょうど 2 枚、読み込みの失敗）と、文字では見分けられないこと（id が同じかどうか、乱数による順番）は、次の節「単体テストで確かめる条件（UT）」で確かめる。

### 受け入れテストの前提

- DB はテスト全体の前に 1 回だけ空になり、テストごとには空にならない。ほかの spec が残したカード（表も裏も同じ文字のカードが複数ある。例: 「quiz-apple／りんご」）も `/flashcards` に出る。
- カードは seed ではなく、各テストの中で `/cards/new` から追加する（`e2e/quiz.spec.ts`・`e2e/review.spec.ts` と同じ）。
- **準備**: 各テストの最初に、`e2e/review.spec.ts` と同じやり方で、表が次の文字のカードを `/cards` からすべて削除する。そのあとで各 AC の Given のカードを追加する。こうすると、そのテストで追加したカードは、表の文字ごとにちょうど 1 枚になる。
  - 「flash-apple」「flash-banana」「flash-cherry」
  - 「flash-long-」のあとに「a」を 189 個続けた 200 文字（AC10 で使う）
- **N**: Given のカードを追加したあと、`/cards` の一覧の項目（`listitem`）を数えた数。検索欄が空のとき、一覧にはすべてのカードが 1 枚につき 1 項目で表示される。
- **カードを探す**: `page.getByRole("main").getByRole("button")`。
- **1 枚進める**: 表が表示されているカードを押して面のラベル「裏」が表示されるのを待ち、もう一度押して面のラベル「表」が表示されるのを待つ。
- 受け入れテストが文字で確かめるのは、そのテストで追加したカード（表の文字ごとにちょうど 1 枚）だけにする。ほかの spec のカードは同じ文字のものが複数あるので、「直前とは別のカードか」「同じカードが 2 回出ていないか」を文字で比べない（UT2〜UT4 で、id で確かめる）。
- 文言は `getByText(…, { exact: true })` で探す。

### 受け入れテストで確かめる条件

- AC1（表を表示する）
  - Given 準備のあと、カード「flash-apple／りんご」を追加した
  - When `/flashcards` を開き、「flash-apple」が表示されるまで 1 枚ずつ進める（多くても N 枚）
  - Then 見出し「カードモード」、面のラベル「表」、「flash-apple」、「カードを押すと裏を表示します」、リンク「カード一覧へ」が表示される。「りんご」、面のラベル「裏」、「カードを押すと次のカードを表示します」は表示されない。`main` の中のボタンは 1 個である
- AC2（表を押すと裏を表示する）
  - Given 準備のあと、カード「flash-apple／りんご」を追加し、AC1 と同じ手順で「flash-apple」の表を表示した
  - When カードを押す
  - Then 面のラベル「裏」、「りんご」、「カードを押すと次のカードを表示します」が表示される。「flash-apple」、面のラベル「表」、「カードを押すと裏を表示します」は表示されない
- AC3（裏を押すと次のカードの表を表示する）
  - Given 準備のあと、カード「flash-apple／りんご」「flash-banana／バナナ」を追加し、AC2 と同じ手順で「flash-apple」の裏を表示した
  - When カードを押す
  - Then 面のラベル「表」と「カードを押すと裏を表示します」が表示される。面のラベル「裏」、「カードを押すと次のカードを表示します」、「flash-apple」は表示されない（「flash-apple」はちょうど 1 枚で、カードは 2 枚以上あるので、続けては出ない）
- AC4（一巡で 1 回ずつ表示する）
  - Given 準備のあと、カード「flash-apple／りんご」「flash-banana／バナナ」を追加し、N を数えた
  - When `/flashcards` を開き、最初のカードから 1 枚ずつ進めて、N 枚の表を順に見る
  - Then N 枚のうち、「flash-apple」が表示されたのはちょうど 1 回、「flash-banana」が表示されたのもちょうど 1 回である
- AC5（一巡のあとも続く）
  - Given 準備のあと、カード「flash-apple／りんご」「flash-banana／バナナ」を追加して N を数え、`/flashcards` を開いて N 枚目のカードの裏を表示した
  - When カードを押し、そこからさらに 1 枚ずつ進めて、次の N 枚の表を順に見る
  - Then カードを押した直後に、見出し「カードモード」、面のラベル「表」、「カードを押すと裏を表示します」が表示される（終わりの画面にならない）。次の N 枚のうち、「flash-apple」が表示されたのはちょうど 1 回である
- AC6（カード一覧へ戻る）
  - Given `/flashcards` を開いている
  - When リンク「カード一覧へ」を押す
  - Then `/cards` へ移動し、見出し「カード一覧」が表示される
- AC7（不正解のカードは、カードモードで見ても復習に残る）
  - Given 準備のあと、カード「flash-banana／バナナ」を追加し、`/quiz` の 1 問目「flash-banana」に「みかん」と答えて不正解にした
  - When `/flashcards` を開いて「flash-banana」の表と裏を表示し、そのあと `/review` を開く
  - Then `/review` の「1問目」に「flash-banana」が表示される
- AC8（正解したカードは、カードモードで見ても復習に出ない）
  - Given 準備のあと、カード「flash-cherry／さくらんぼ」を追加し、`/quiz` の 1 問目「flash-cherry」に「さくらんぼ」と答えて正解にした
  - When `/flashcards` を開いて「flash-cherry」の表と裏を表示し、そのあと `/review` を開いて問題を最後まで 1 問ずつ進める（`e2e/review.spec.ts` と同じやり方）
  - Then `/review` のどの問題にも「flash-cherry」は表示されない
- AC9（キーボードで操作できる）
  - Given 準備のあと、カード「flash-apple／りんご」を追加し、AC1 と同じ手順で「flash-apple」の表を表示した
  - When カードにフォーカスして Enter を押し、続けて Space を押す
  - Then Enter のあと、面のラベル「裏」と「りんご」が表示される。Space のあと、面のラベル「表」と「カードを押すと裏を表示します」が表示される
- AC10（長い文字）
  - Given 準備のあと、表が「flash-long-」のあとに「a」を 189 個続けた 200 文字、裏が「あ」を 200 個続けた 200 文字のカードを追加した
  - When `/flashcards` を開き、そのカードの表が表示されるまで 1 枚ずつ進め（多くても N 枚）、カードを押して裏を表示する
  - Then 表のときは表の 200 文字が、裏のときは裏の 200 文字が省略されずに表示される。どちらのときも画面に横スクロールが出ない（ページの `scrollWidth` が `clientWidth` を超えない）

## 単体テストで確かめる条件（UT）

受け入れテストでは確かめられないので、vitest の単体テストで確かめる。カードは id の違うものをテストの中で用意し、「同じカードか」は id で比べる。乱数は、テストから決まった値に差し替えられるようにする。

- UT1（順番がランダムである）
  - Given id の違うカードが 5 枚ある
  - When 乱数を差し替えて、順番を何度か決める
  - Then 乱数によって異なる順番になる。どの順番も 5 枚すべてをちょうど 1 回ずつ含む
- UT2（一巡ですべてのカードを 1 回ずつ表示する）
  - Given id の違うカードが 4 枚あり、そのうち 2 枚は表も裏も同じ文字である
  - When 最初のカードから 4 枚目まで進める
  - Then 表示された 4 枚の id は、4 枚のカードの id がちょうど 1 回ずつである（文字が同じ 2 枚も、それぞれ 1 回ずつ出る）
- UT3（続けて同じカードを表示しない）
  - Given id の違うカードが 3 枚あり、乱数を「次の一巡の最初が、前の一巡の最後と同じカードになる」値に差し替えた
  - When 3 巡ぶん（9 枚）進める
  - Then どのカードも、直前に表示したカードと id が違う。どの一巡も 3 枚すべてをちょうど 1 回ずつ含む
- UT4（カードがちょうど 2 枚）
  - Given id の違うカード A・B の 2 枚だけがあり、最初に A が表示された
  - When 乱数をどの値に差し替えても、3 巡ぶん（6 枚）進める
  - Then 表示される順は A → B → A → B → A → B である（一巡目が A → B なら、二巡目は必ず A から始まる）
- UT5（カードが 1 枚だけ）
  - Given カードが 1 枚だけあり、その裏が表示されている
  - When カードを押す
  - Then 同じカードの表が、面のラベル「表」と「カードを押すと裏を表示します」とともに表示される
- UT6（カードが 0 枚）
  - Given カードが 1 枚もない
  - When カードモードの画面を表示する
  - Then 「カードがありません」とリンク「カード一覧へ」（行き先 `/cards`）が表示される。ボタン・面のラベル・操作の説明は表示されない
- UT7（読み込みの失敗）
  - Given カードの読み込みに失敗した
  - When `/flashcards` の読み込み失敗の画面（`src/app/flashcards/error.tsx`）を表示する
  - Then 見出し「カードを読み込めませんでした」、「時間をおいてもう一度お試しください。」、ボタン「もう一度読み込む」が表示され、エラーの中身は表示されない。ボタンを押すと、もう一度読み込む

単体テストに回した理由:

- UT1〜UT4: 受け入れテストの DB には、ほかの spec が残した「表も裏も同じ文字のカード」が複数あり、画面の文字では別のカードかどうかを見分けられない。乱数を決まった値にすることも、ちょうど 2 枚の状態を作ることもできない。
- UT5・UT6: カードを 0 枚・1 枚にするには、ほかの spec が残したカードもすべて削除する必要がある。テストが重くなり、ほかの spec に影響するので、受け入れテストでは作らない。
- UT7: `/flashcards` は `/quiz` と同じくサーバー側でカードを読むので、Playwright からは読み込みの失敗を起こせない。既存の画面も単体テスト（`src/app/cards/error.test.tsx`）だけで確かめている。`src/app/flashcards/error.tsx` は `/quiz`（`src/app/quiz/error.tsx`）と同じく `../cards/error` をそのまま使う。読み込みに失敗したときにこの画面へ進むところ（`/quiz` と同じく、ページがエラーを投げる）は、テストでは確かめない。

## そのほかの完成の条件

- 既存の受け入れテスト（`e2e/` の各 spec）と単体テストを変えずに、すべて通る（`/quiz`・`/review`・`/cards` の振る舞いと文言を変えていない）。
- CI の `check`（lint・整形・型・単体テスト・ビルド）と `e2e` が通る。

## UI のデザイン

新しいデザインは要らない。デザインシステムはまだないので、既存の画面の見た目と書き方に合わせる。

- ページの枠（幅・余白）と見出しは `/quiz`（`src/app/quiz/page.tsx`）と同じにする。
- 補足の文（操作の説明、「カードがありません」）とリンクは `/quiz`（`src/app/quiz/quiz.tsx`）の文字色・下線に合わせる。
- カードは枠線のある大きめのボタンにし、カードの文字は `/quiz` の問題の文字と同じくらい大きくする。ライト・ダークの両方で読めるようにする。
- めくるアニメーションは付けない。

## 対象外

- 一定時間で自動的にめくる・次へ進む機能
- 対象のカードの絞り込み（検索結果だけ、間違えたカードだけ、枚数の指定など）
- 裏から先に表示するモード（裏 → 表）
- 前のカードに戻る操作
- 「覚えた」「覚えていない」の記録、答えの結果（`card_results`）の読み書き、見た回数などの統計
- 何枚目か・全部で何枚か・何巡目かの表示
- 終わりの画面、「もう一度」のリンク
